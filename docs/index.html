puffy

An OpenBSD native AI agent that reads the man pages so it can tell you which man page to read.

Only two hallucinations in the default install, in a heck of a long time! (We are counting the ones we noticed.)

puffy runs on your OpenBSD machine. It configures the system, writes code, and teaches you how OpenBSD works. In practice that means quoting the manual at you, with section numbers, until you start reading it yourself.

OpenBSD has the finest manual pages ever written. They are complete, correct, terse, and searchable with man -k. Generations of users have been told to read them. Generations of users have instead asked on a mailing list. puffy is what happens when someone finally gives up and builds a robot to read them out loud.

Yes, it is AI. We are aware. We are sorry. It asks before it touches anything.

Install

On OpenBSD 8.0/amd64, as a user who can doas:

ftp -o - https://raw.githubusercontent.com/elevenarms/puffy/main/get.sh | doas sh

Yes, that is piping a script from the internet into a root shell. It fetches a tarball and checks it with signify(1) against our release key before it installs anything, which is more than most curl | sh can say. If that still makes you itch, read get.sh first. It is about 50 lines. We would think less of you if you did not.

Then, as your normal user:

$ puffy

The first run walks you through setup. Full instructions: SETUP.md.

What it looks like

$ puffy enable ntpd and show me how to check it

# rcctl(8) manages daemons. "enable" writes ntpd_flags to
# /etc/rc.conf.local so ntpd starts at boot; "start" starts it now.
# script
doas rcctl enable ntpd
doas rcctl start ntpd
doas rcctl check ntpd
# end
Run this script? [y]es [n]o [e]xplain [q]uit: _

Press e and it explains every command and flag, and which page of the manual says so. Press n and tell it why it is wrong. It will take it better than most people on the mailing lists.

Goals

  • Strive to make the AI as unnecessary as possible. Every answer comes with the man page it came from, so next time you can skip the AI.
  • Prefer the base system. pf, httpd, relayd, smtpd, rcctl, doas. If puffy reaches for a package, it has to explain itself.
  • Validate before reloading. pfctl -nf exists for a reason, and the reason is that you locked yourself out of an ssh session in 2009.
  • Never run anything you did not approve. puffy asks. Every. Time.
  • Keep working when the cloud does not. See below.
  • Be secure by default, within reason, which for an AI agent is not very much reason. We did what we could.

Features

Every man page All 5,400+ amd64 manual pages from OpenBSD 8.0, plus the 12,571 prebuilt packages and their pkg-readmes, indexed on your disk. Keyword search (SQLite FTS5) and meaning search (local embeddings, sqlite-vector with 4-bit TurboQuant) work together, all on your CPU.
Works offline No network? No API key? The cloud on fire? puffy shrugs and searches the man pages locally, like it is 1996 and you are on a 14.4k modem. Type retry when civilization returns.
Private Inference goes to TrustedRouter on confidential-compute hardware with end-to-end encryption and zero data retention. Your man page searches never leave the machine at all.
pledge(2) puffy pledges itself after startup. We looked into pledging the model. There is no promise for "stop being confident."
No tool calling The model answers in plain text, one action per reply, ending in # end. puffy stops listening right there, so the model cannot make up the output of commands it never ran. It tried.
Teaching mode On by default. Every task ends with what changed, how to undo it, and two or three man pages to read next. You will read them, right?
No packages One tarball. Base system libraries only. The embedder runs on any 64-bit x86 CPU. AVX not required, GPU not required, patience optional.

Frequently Asked Questions

Q: Is this AI?
A: Yes. Please do not tell anyone.

Q: Why not just read the man page?
A: You should. puffy will tell you which one. It reads them too, and it cites them, and it is the only part of this stack that has done the reading.

Q: Can it run as root?
A: It can. It will tell you not to, and suggest doas.conf(5). That is the most OpenBSD thing it does.

Q: Will it ever rm -rf /?
A: Not without asking you first, and you will say no, because you read the script. You did read the script.

Q: Does it run on my VAX?
A: No. amd64 only. The VAX may file a complaint by mail.

Q: Is this an official OpenBSD project?
A: No. Absolutely not. See the bottom of this page. The OpenBSD developers write the man pages; we just made a machine that quotes them back at you with unearned confidence.

Q: It gave me a wrong answer.
A: It is AI. Check the man page it cited, then open an issue with the log from ~/.puffy/logs/. Every run is logged in full, so we can see exactly how it got there.
